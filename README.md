# Бот УВД

Telegram LorSwelL
Discord LorSwelL

Discord-бот для кадрового учёта на одном сервере: заявки (курсант, перевод, гос. сотрудник), переводы между отделами, увольнения, повышения, склад. Всё настраивается через файл `.env`.

## Что делает бот

- **Заявки.** В канале кнопки: «Курсант», «Перевод», «Гос. сотрудник». После заполнения формы заявка попадает в рабочий канал. Сотрудники с нужной ролью принимают, отклоняют или отправляют на редактирование. При принятии бот выдаёт роли, меняет ник. Курсанту в ЛС уходит приказ и кнопка в канал экзамена.

- **Переводы между отделами (ГРОМ, ППС, ОСБ, ОРЛС).** В каждом отделе свой канал с кнопками «Подать заявку из [отдела]». Сначала одобряет свой отдел (если не из Академии), потом — отдел назначения. Бот снимает старые роли отдела и ранги, выдаёт роль нового отдела и должность. Заявку «из Академии» могут подать только с ролью «Прошедший Академию».

- **Админ-перевод в ППС.** Отдельный канал с кнопками ГРОМ / ОСБ / ОРЛС. Начальник вводит ID и причину — бот переводит в ППС.

- **Увольнение.** Кнопка «Подать заявление» в канале. Рапорт с ФИО и причиной. При выходе участника с сервера бот создаёт авто-рапорт. Сотрудники с нужной ролью одобряют или отклоняют. При одобрении бот снимает роли (кроме заданных в настройках), выдаёт роль «Уволен», меняет ник.

- **Повышения.** В каналах повышений сообщение «Подать рапорт» с выбором звания и формой. У рапорта кнопки «Одобрить» и «Отклонить». Сообщения создаются при старте бота или командами `/orls_promotion_setup`, `/promotion_setup_all` и т.д. При одобрении старые звания снимаются, выдаётся новая роль по настройкам.

- **Повышения в Академии.** В канале Академии: рапорт на повышение и заявка на перевод в отдел. При повышении до сержанта выдаётся роль «Прошедший Академию».

- **Склад.** Заявки на выдачу снаряжения. Сотрудник склада выдаёт, отклоняет или редактирует. Есть лимиты по категориям и кулдаун между заявками от одного человека. Записи в канал аудита склада.

- **Аудит.** События «принят», «повышен», «уволен» можно отправлять в Google Form (если задан `AUDIT_FORM_URL`).

## Запуск

Нужен **Python 3.11** или новее.

**На Windows:** для **Python 3.14+** у пакета `aiohttp` может не быть готовых сборок (wheel). Тогда `pip install -r requirements.txt` попытается собрать его из исходников и потребует **Microsoft Visual C++ 14.0 or greater** ([Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/)). Проще всего использовать **Python 3.11 или 3.12** — для них все зависимости ставятся без компиляции.

1. Скопируй `.env.example` в `.env`.
2. Открой `.env` и заполни токен, ID сервера, каналов и ролей (вместо 0 подставь свои числа).
3. **Файл `.env` не коммить в репозиторий** — в нём токен и секреты (уже в `.gitignore`).
4. При первом запуске проверка окружения подскажет, чего не хватает. Если токен пустой или не задан, бот выведет в лог сообщение и завершится до попытки входа в Discord.
5. Установи зависимости и запусти:

```bash
pip install -r requirements.txt
python main.py
```

(Флаг **-r** обязателен: без него pip попытается найти пакет с именем «requirements.txt».)
Для фиксации версий зависимостей можно дополнительно использовать `constraints.txt`:
`pip install -r requirements.txt -c constraints.txt`.

Точка входа — `main.py`. Переменные в `.env` сгруппированы по блокам с комментариями. Обязательно нужны: **python-dotenv** (подгрузка `.env`), **discord.py**, **aiosqlite**, **aiohttp**.

## Слэш-команды

Доступны только тем, у кого роль на сервере **выше роли бота**.

| Команда | Назначение |
|--------|------------|
| `/ping` | Задержка бота (мс). |
| `/diag` | Диагностика: заявки, кэш, база. |
| `/diag_clean_orphans` | Удалить из базы записи, у которых сообщение в Discord уже удалено. |
| `/clear_firing` | Удалить старые рапорты на увольнение (по умолчанию старше 7 дней). |
| `/orls_promotion_setup` | Создать в этом канале сообщение «Подать рапорт» для ОРЛС. |
| `/osb_promotion_setup` | То же для ОСБ. |
| `/grom_promotion_setup` | То же для ГРОМ. |
| `/pps_promotion_setup` | То же для ППС. |
| `/promotion_setup_all` | Создать сообщения «Подать рапорт» во всех каналах повышения. |

## Роли (кто что делает)

Всё задаётся в `.env`:

- **STAFF_ROLE_ID** — приём/отклонение заявок «Курсант».
- **TRANSFER_STAFF_ROLE_ID**, **GOV_STAFF_ROLE_ID** — заявки «Перевод» и «Гос. сотрудник».
- **FIRING_STAFF_ROLE_ID** — рапорты на увольнение.
- **FIRING_SENIOR_ROLE_ID** — кнопка «Уволить» по ID без рапорта.
- **WAREHOUSE_STAFF_ROLE_ID** — заявки на склад.
- **ROLE_CHIEF_***, **ROLE_DEPUTY_*** — начальники и замы отделов (переводы и админ-перевод).
- **PROMOTION_CH_***** — каналы повышений и роли кадровика.
- **ROLE_ACADEMY**, **ROLE_DEPT_ACADEMY**, **ROLE_RANK_ACADEMY_*** — роли Академии.
- **ROLE_PASSED_ACADEMY** — «Прошедший Академию», выдаётся при повышении до сержанта.

## База данных (SQLite)

По умолчанию файл `data/bot.db` (или путь из **DB_PATH** / **DATABASE_URL**). Таблицы: заявки, рапорты на увольнение и повышение, заявки склада, переводы между отделами, черновики рапортов, сессии и кулдауны склада. Подробный список — в коде `database.py`.

## Восстановление кнопок при старте (RESTORE_*)

После перезапуска бот восстанавливает кнопки под сообщениями из базы. В `.env` можно задать:

- **RESTORE_MAX_ITEMS** — максимум записей одной категории для восстановления (по умолчанию 1000). Значение **0 или пусто** трактуется как **1000** (ограничение по умолчанию), чтобы не загружать при старте все записи без лимита.
- **RESTORE_MAX_DAYS** — восстанавливать только записи не старше N дней (0 = не ограничивать по дате).
- **RESTORE_BATCH_SIZE** и **RESTORE_BATCH_DELAY_SEC** — размер батча и пауза между батчами при восстановлении (снижают нагрузку на API Discord).

Лимиты применяются ко всем категориям: заявки, увольнения, повышения, склад, переводы между отделами.

## Логирование

В `.env`: **LOG_FILE** (по умолчанию `bot.log`), **LOG_LEVEL** (DEBUG, INFO, WARNING, ERROR). Лог пишется в файл и в консоль. Ротация: до 2 MB на файл, хранится 5 файлов.
При указании **LOG_ALERT_CHANNEL_ID** и **LOG_ALERT_LEVEL** критичные/ошибочные сообщения дублируются в указанный канал Discord.

## Минимальный .env для запуска

```env
DISCORD_BOT_TOKEN=твой_токен
GUILD_ID=123456789012345678
PROMOTION_CH_01=ID_канала:ID_роли
RANKMAP_01=Рядовой -> Младший Сержант:ID_роли_звания
```

Остальные переменные — в `.env.example` с пояснениями. Каналы подачи рапортов по отделам (**PROMOTION_APPLY_CHANNEL_OSB**, **GROM**, **PPS**, **ORLS**) опциональны: если не заданы, берутся по порядку из **PROMOTION_CH_*** (в логе будет предупреждение).

## Устройство

- Точка входа: `main.py`. События в `events.py`, команды в `commands/`, кнопки и формы в `views/` и `modals/`, логика в `services/`.
- После перезапуска кнопки под сообщениями восстанавливаются из базы (с лимитами и семафором, см. RESTORE_* в `.env`).
- Каналы и роли кэшируются для быстрого ответа на нажатия.
